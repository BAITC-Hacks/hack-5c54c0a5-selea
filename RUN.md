# Voice Router MVP

Прототип объединяет продуктовую модель PolyAI (понимание свободной речи и маршрутизация звонка) с технической моделью Retell AI (голосовой интерфейс, workflow, actions, handoff и трассировка).

## Запуск

PowerShell:

```powershell
$env:OPENAI_API_KEY="ваш-ключ"
$env:OPENAI_MODEL="gpt-4o-mini"
python app.py
```

Откройте `http://127.0.0.1:8000`.

Без `OPENAI_API_KEY` приложение запускается в демонстрационном режиме. Этот режим нужен только для проверки интерфейса и не считается решением кейса: при оценивании должен быть включён LLM.

## Что реализовано

- маршрутизация по 40 сценариям и трём системным маршрутам;
- Structured Outputs с массивом сценариев для multi-intent;
- границы всех 40 сценариев в стабильном промпте, примеры RU/KK и смешанной речи;
- короткое объяснение и альтернативы для супервизора;
- состояние диалога, слоты и стек переключения тем;
- политика уверенности и передача оператору после двух неуверенных решений;
- preview необратимых действий;
- голосовой ввод и TTS через OpenAI API, браузерный TTS как резерв;
- отображение маршрута, действий, слотов и задержки;
- одна команда запуска без установки зависимостей.

## Проверка точности

После настройки `OPENAI_API_KEY`:

```powershell
python predict_dev.py
python evaluate.py predictions.json dev_utterances.json
```

### Пограничные случаи

Локальные регрессии логики состояния (без API и расходов):

```powershell
python -B -m unittest -v test_router
```

Это проверки кода с подставленными ответами модели, **не замер точности LLM**.
Отдельный набор `edge_dialogues.json` содержит 20 диалогов: смена темы, возврат,
несколько намерений без явного союза, отрицания, отмена запроса, RU↔KK и 10 реплик.
Эталонные ответы не передаются модели. Это авторский регрессионный набор, не независимый benchmark.

Для проверки реальной модели задайте ключ в окружении и выполните:

```powershell
python -B evaluate_edges.py
```

Либо через уже **перезапущенный с новым кодом** сервер с ключом:

```powershell
python -B evaluate_edges.py --url http://127.0.0.1:8000
python -B evaluate_edges.py --case mixed_multi_intent --output edge_report_mixed.json
```

Второй пример запускается напрямую с ключом в окружении. Результат — `edge_report.json`:
точность первого маршрута, полного набора и порядка, multi-intent recall, проверки очереди,
языка, слотов и возврата к теме, доля полностью прошедших диалогов, router p50/p95 и доля ≤500 мс.
Код возврата 1 означает провал хотя бы одного диалога; 2 — ошибка запуска.
Демо-режим и сервер со старым кодом не принимаются за замер LLM.
Отчёт содержит тексты диалогов и слоты: не публикуйте его с реальными персональными данными.

Кэш готовых решений отключён при оценке, кэш промпта провайдера может работать.
Замеры относятся только к маршрутизации, не к STT/TTS и не к полной задержке голосового ответа.
500 мс — целевой показатель, а не гарантия; точность и задержку нужно измерять на реальном API.

### Политика маршрутизации

- История хранит 10 пар реплик с ролями и языком. В модель передаются также активный сценарий,
  очередь, приостановленные темы и известные слоты.
- История передаётся отдельными сообщениями Responses API; текущая реплика — последним
  сообщением `user`. Для GPT-4o/4.1 задан `temperature=0`; это не гарантирует идентичность ответов.
- Каждый сценарий содержит `request_text`: цитату, по которой проверяется порядок упоминания.
  Если дополнительное намерение уже есть в контексте, а модель цитирует только старую реплику,
  оно остаётся в контексте, но не объявляется новым запросом текущей реплики.
- Новый запрос приостанавливает старую тему; очередь не стирается при заполнении слота.
  Только явно закрытые клиентом запросы удаляются через `closed_scenarios`.
- Confidence — оценка модели, а не откалиброванная вероятность. При confidence <0.75
  или альтернативе ≥0.65 с отрывом <0.10 робот уточняет запрос и не выполняет действие.
  Эти пороги — стартовая эвристика, её нужно проверять на независимых диалогах.
- Подтверждение принимается только отдельной короткой репликой. «Не подтверждаю» и
  «да, но…» идут в LLM, а не запускают ранее подготовленное действие.
- Лексический поиск используется для подбора кандидатов, а не окончательного решения.
  Локальный fast path по умолчанию выключен; экспериментальный режим разрешает лишь
  дословные примеры каталога для сценариев без обязательных слотов.
- Кэш ответов хранит только однозначные одноинтентные решения первой реплики без слотов.
  Кэширование не подтверждает правильность решения; для тестов оно отключается.

### Последние локальные замеры — 23 сентября 2026

Один финальный прогон каждой модели на этих же 20 авторских диалогах, после доработки на этом наборе.
Это регрессии, **не независимая оценка обобщения и не гарантия 100% точности**.
Модель по умолчанию оставлена `gpt-4o-mini`. STT/TTS не менялись.

| Проверка | gpt-4o-mini | gpt-4.1-mini (сравнение) |
| --- | ---: | ---: |
| Основной маршрут | 41/41 | 41/41 |
| Полный набор и порядок намерений | 41/41 | 41/41 |
| Диалоги со всеми пройденными проверками | 13/20 | 17/20 |
| Проверки языка | 3/6 | 6/6 |
| Router p50 / p95 | 1670 / 2073 мс | 1790 / 2614 мс |
| Выбор маршрута ≤500 мс | 0/41 | 0/41 |

Полные трассы — `edge_report.json` и `edge_report_41mini.json` (не добавляются в Git).
Остались ошибки определения языка, извлечения слотов и управления темами: модель иногда
ошибочно закрывает тему вместо приостановки или не отмечает явно завершённый запрос.
Локальные тесты политики состояния проходят 30/30, но они не подтверждают правильность решений LLM.
Сравнительные прогоны выполнялись параллельно: задержки ориентировочные, не нагрузочный benchmark.

Формат структурированного ответа и параметры API сверены с
[OpenAI Docs](https://developers.openai.com/api/docs/guides/structured-outputs).
Совместимость сравнительной модели — [GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini).

## Переменные окружения

- `OPENAI_API_KEY` — включает реальный LLM Router;
- `OPENAI_MODEL` — модель, по умолчанию `gpt-4o-mini`;
- `OPENAI_STT_MODEL` — распознавание речи, по умолчанию `gpt-4o-mini-transcribe`;
- `OPENAI_TTS_MODEL` — синтез речи, по умолчанию `gpt-4o-mini-tts`;
- `OPENAI_TTS_VOICE` — голос синтеза, по умолчанию `marin`;
- `OPENAI_SERVICE_TIER` — режим Router API, по умолчанию `fast` с автоматическим откатом;
- `OPENAI_PROMPT_CACHE_KEY` — стабильный ключ кэша промпта, по умолчанию `voice-router-v4`;
- `OPENAI_MAX_OUTPUT_TOKENS` — лимит структурированного ответа Router, по умолчанию `1200` (не заданная длина ответа);
- `ROUTER_EXPERIMENTAL_FAST_PATH=1` — экспериментальный локальный путь, по умолчанию выключен;
- `OPENAI_BASE_URL` — базовый адрес OpenAI-совместимого Responses API;
- `PORT` — порт, по умолчанию `8000`.
